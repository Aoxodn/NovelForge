> 前置版本：0.9.12

## 一、版本概述

### 1.1 解决的核心问题

| # | 问题 | 现状 | 目标 |
|---|------|------|------|
| 1 | 画布只有卷节点，人物完全不可视 | 37张人物卡躺在数据库里，画布上看不到 | 人物节点上画布，关系可视化 |
| 2 | 进入卷内只有章节列表，无可视化 | VolumeView 是纯卡片列表 | 卷内同样是画布，章节+人物+关系 |
| 3 | 同对节点多边重叠，标签打架 | 按id均匀偏移，不按类型分道 | 类型分道+标签锚定效应端 |
| 4 | 人物关系类型匮乏，仅适配玄幻 | 无关系系统 | 5大类25+子类型，全题材通用 |
| 5 | 卷节点信息单薄 | 只有标题+字数+进度条 | 核心人物行+伏笔徽标+事件标签 |

### 1.2 核心理念

**分形画布**：叙事结构天然是递归的（书→卷→章→场景），同一套渲染引擎在三个粒度上递归使用。

**语义路由**：边的外观编码含义，读者不读标签也能区分关系类型。

**五层架构**：领域模型 → 适配层 → 布局引擎 → 渲染内核 → 交互管理层，层间只通过定义好的接口通信。

## 二、架构升级：分形画布

### 2.1 三级画布体系

```
L1 全书画布 (StoryMap)          现有，增强人物层
  │ 双击卷节点
  ▼
L2 卷内画布 (VolumeCanvas)      【新增核心】替换 VolumeView 的章节列表
  │ 双击章节节点
  ▼
L3 章节发展图 (ChapterDev)      后续迭代，本次预留接口
```

每一级使用同一套渲染内核（SVG连线 + DOM节点 + view transform + 指针交互），仅数据源和节点粒度不同。

### 2.2 五层架构

```
⑤ 交互管理层  指针事件 / 手势 / 选择 / 层级导航栈
④ 渲染内核    纯函数 (nodes, edges, view) → DOM，不关心节点语义
③ 布局引擎    可插拔策略，输入数据+约束 → 节点坐标
② 适配层      领域数据(volumes/chapters/characters) → 通用画布数据
① 领域模型    SQLite 表结构
```

**约束**：禁止跨层调用。渲染内核不知道"卷"是什么，只知道 type='volume' 的 212×92 方形节点。

### 2.3 通用画布数据模型

```typescript
type CanvasNodeType = 'volume' | 'chapter' | 'character' | 'scene';

interface CanvasNode {
  id: number;
  type: CanvasNodeType;
  x: number; y: number;     // 世界像素
  w: number; h: number;     // volume/chapter=212×92; character=圆形; scene=小方块
  data: Record<string, any>; // 标题、字数、角色、颜色等
}

interface CanvasEdge {
  id: number;
  from: number; to: number;
  kind: 'plot' | 'character' | 'appearance'; // 剧情边/人物关系边/出场边
  edgeType: number;       // 剧情:0顺序1因果2分支3汇合4伏笔5平行6闪回; 人物:关系大类
  label: string;
  color?: string;
  status?: number;        // 伏笔:0活跃1已回收2失效
}
```

### 2.4 层级导航栈

```typescript
type CanvasLevel =
  | { kind: 'L1' }
  | { kind: 'L2'; volumeId: number }
  | { kind: 'L3'; chapterId: number };

// 每级栈帧保存视图状态，返回时恢复
interface LevelFrame {
  level: CanvasLevel;
  view: { x: number; y: number; k: number };
  selectedId: number | null;
  layoutStrategy: string;
}
```

面包屑：`故事地图 › 第一部 地球往事 › 第3章 射手和农场主`

### 2.5 布局策略可插拔

| 策略 | 适用级别 | 原理 |
|------|---------|------|
| swimlane（泳道分层） | L1 | 主线居中，支线浮上，暗线沉下 |
| linear-branch（线性分支） | L2 默认 | 主干横向，支线/闪回上下偏移 |
| radial（辐射） | L2 可选 | 核心冲突居中，角色线辐射 |
| force（力导向） | L2 可选 | 节点互斥边吸引，自动解纠缠 |
| timeline（时间线） | L3 | 严格按叙事时间左→右 |

策略接口：`layout(nodes, edges, constraints) => Map<id, {x,y}>`

布局继承：L1 中属于"暗线"的卷，进入 L2 时默认 radial 布局；"主线"卷默认 linear-branch。

## 三、L1 全书画布增强

### 3.1 跨卷人物轨迹带

- 触发条件：人物在 ≥2 个卷有提及记录
- 视觉：从首出场卷到末出场卷，3px 半透明纵向带（opacity 0.25），颜色=人物角色色
- 多人物轨迹带垂直错开，间距 0.02（归一化坐标）
- 数据来源：character_mentions 聚合，纯渲染派生，不存库

### 3.2 卷节点信息增强

```
┌─────────────────────────────┐
│ 阶段1              🔴 2伏笔 │  ← 伏笔徽标：活跃伏笔数
│ 第一部 地球往事              │
│ 37章 · 165,357字             │
│ ▓▓▓▓▓▓▓▓▓▓░░░░ 进度条        │
│ ○主角A ○主角B ○配角C ○配角D    │  ← 核心人物行：提及Top4小圆头像
│ ── 古筝行动 ── 智子锁死 ──    │  ← 关键事件标签
└─────────────────────────────┘
```

- 核心人物行：查 character_mentions 按 volume_id 聚合，取 mention_count 前 4
- 伏笔徽标：查 story_edges WHERE edge_type=4 AND status=0，匹配 from_node 或 to_node
- 事件标签：从 volumes.summary 提取前 2 个关键短语（后续可加 volume_events 表）

### 3.3 L1 人物节点（精简层）

L1 上只显示**跨卷核心人物**（≥2 卷出场），圆形节点，位置在出场卷之间的连线上方。不显示全部人物（避免 L1 过载）。

## 四、L2 卷内画布（新增核心）

### 4.1 整体布局

```
┌──────────────────────────────────────┬───────────────────┐
│ 工具栏：返回 │ 自动布局 │ 布局策略 │ 筛选  │  选中详情面板    │
│ ┌────────────────────────────────┐  │  ┌─────────────┐  │
│ │                                │  │  │ 章节/人物信息 │  │
│ │  [章1]──→[章2]──→[章3]         │  │  │ 章纲/笔记     │  │
│ │    ↑       ↓ 因果              │  │  │ 出场人物列表  │  │
│ │ [章5]←──[章4]                  │  │  │ 关联伏笔      │  │
│ │    🠑 人物关系层 🠑              │  │  │ [打开正文]   │  │
│ │ [人物A]─母女→[人物B]           │  │  └─────────────┘  │
│ │ [人物C]──搭档→[人物D]            │  │                   │
│ └────────────────────────────────┘  │                   │
└──────────────────────────────────────┴───────────────────┘
  左侧画布 65%                          右侧详情 35%
```

### 4.2 节点类型

#### 章节节点（方形，主节点）

| 属性 | 说明 |
|------|------|
| 标题 | 章节标题 |
| 字数 | 小字 |
| 状态色 | 草稿=灰边框、完稿=绿边框 |
| 节点类型 | 常规/转折/高潮/结局（chapters 预留，可手动标注） |
| 大小 | 固定 212×92 |

#### 人物节点（圆形，叠加层）

| 属性 | 说明 |
|------|------|
| 大小 | r = 14 + log₂(本卷提及次数) × 2.5 |
| 颜色 | 主角=蓝、配角=灰、反派=红、功能性=橙 |
| 位置 | 围绕出场章节辐射分布，不与章节节点重叠 |
| 显隐 | 工具栏"人物层"开关 |

### 4.3 边类型（卷内三类边共存）

#### A. 剧情边（章节→章节）

| edge_type | 含义 | 视觉 | 泳道 |
|-----------|------|------|------|
| 0 顺序 | 叙事顺序 | 实线灰 | 0 中线 |
| 1 因果 | A章事件导致B章 | 实线蓝+箭头 | +1 上方 |
| 2 分支 | A章引出多条线 | 虚线蓝 | +2 上方 |
| 3 汇合 | 多条线汇入B章 | 虚线蓝 | -1 下方 |
| 4 伏笔回收 | A章伏笔B章回收 | 点线紫 | -2 下方 |
| 5 平行叙事 | A、B章同时发生 | 双线 | +3 上方 |
| 6 闪回/插叙 | B章回忆A章 | 反向红虚线 | -3 下方 |

#### B. 人物关系边（人物→人物）

见第五章广义关系体系。使用独立偏移空间，不与剧情边争道。

#### C. 出场边（人物→章节）

浅灰细线（opacity 0.25），线粗按该章提及次数。辅助视觉，可通过"出场边"开关隐藏。

### 4.4 章节布局算法（linear-branch 默认策略）

```
输入: 该卷章节（按 sort_order）+ 章间边
输出: 每章 {x, y} 世界坐标

1. 主干章节（在最长顺序链上，无分支边）:
   x = 80 + i * 280
   y = WORLD_H / 2

2. 支线章节（有分支边）:
   从分叉点向上/向下偏移 120px
   同方向多条支线再错开 80px

3. 闪回章节:
   主干下方 160px，反向箭头连回被回忆章节

4. 人物节点:
   围绕出场章节的 y 位置辐射
   x = 出场章节 x ± 40~80px 随机偏移
   同章多人垂直堆叠，间距 50px
```

章节位置**不存库**，每次进入 L2 时由布局算法计算。作者可通过切换布局策略改变排列，不需要手动拖 30 个节点。

### 4.5 右侧详情面板

**选中章节节点**：
- 章节标题、字数、状态
- 章纲（chapters.summary，可编辑，600ms 防抖）
- 作者笔记（chapters.notes，可编辑）
- 本章出场人物列表（点击高亮画布对应人物节点）
- 本章关联伏笔（活跃/已回收）
- "打开正文"按钮 → 跳转编辑器

**选中人物节点**：
- 人物名、别名、角色
- 人物备注（可编辑）
- 本卷出场章节列表（点击跳转）
- 关联人物（关系边列表）

## 五、广义人物关系体系

### 5.1 设计原则

- 全题材通用：玄幻/都市/科幻/历史/悬疑/言情均适用
- 分类+子类型：5 大类，每类若干子类型，支持自定义
- 大类定色定线型，子类型定标签文字

### 5.2 五大关系类

#### 类 1：血缘/家族（色 #E1B98F，实线无箭头）

父子、母子、父女、母女、兄弟、姐妹、兄妹、姐弟、祖孙、外祖孙、叔侄、舅甥、姑侄、姨甥、表亲、堂亲、夫妻、婚约、其他亲属

#### 类 2：情感（色 #EAA7B2，实线无箭头）

恋人/情侣、夫妻、暗恋/单相思（单向箭头→被暗恋方）、前任/旧爱、情敌（双向虚线）、暧昧/知己、其他情感

#### 类 3：社会关系（色 #5b8def，实线无箭头）

朋友/挚友、损友/酒肉朋友、师徒/师生（单向→徒弟）、主仆/上下级（单向→下属）、同僚/同事/同学/战友、邻居/网友、其他社会关系

#### 类 4：阵营/对立（色 #EA6668）

盟友/同伙（实线）、敌人/仇人/宿敌（双向虚线）、背叛/被背叛（单向→被背叛方）、受害者/加害者（单向→受害者）、守护者/被守护者（单向→被守护者）、竞争/对手、其他阵营关系

#### 类 5：叙事功能（色 #B56AD9，点线有箭头）

引路者/导师（→被引导者）、绊脚石/对手（→被阻碍者）、镜像/对照组（双向）、催化剂（→被触发者）、见证者/旁观者（→被见证者）、继承者（→继承者）、其他叙事功能

### 5.3 数据模型

```sql
CREATE TABLE character_relations (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    from_char    INTEGER NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
    to_char      INTEGER NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
    rel_category INTEGER NOT NULL,   -- 1血缘 2情感 3社会 4阵营 5叙事
    rel_type     TEXT NOT NULL DEFAULT '',  -- 子类型名，如"母女""师徒"
    label        TEXT NOT NULL DEFAULT '',  -- 自定义补充说明
    direction    INTEGER NOT NULL DEFAULT 0, -- 0双向 1单向(from→to)
    volume_id    INTEGER REFERENCES volumes(id) ON DELETE SET NULL,
    created_at   TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_rel_from ON character_relations(from_char);
CREATE INDEX idx_rel_to ON character_relations(to_char);
CREATE INDEX idx_rel_volume ON character_relations(volume_id);
```

- `volume_id` = NULL：跨卷关系，L1 和 L2 都显示
- `volume_id` = 具体卷：只在该卷 L2 显示
- `rel_type` 为自由文本，UI 提供下拉常用选项 + 允许自定义输入

### 5.4 关系边在各级的显示规则

| 关系范围 | L1 全书 | L2 卷内 |
|---------|---------|---------|
| volume_id=NULL（跨卷） | 显示（跨卷人物之间） | 显示 |
| volume_id=当前卷 | 不显示 | 显示 |
| volume_id=其他卷 | 不显示 | 不显示 |

L1 人物层只显示跨卷核心人物（≥2 卷出场），L2 显示该卷全部出场人物。

## 六、边路由与标签系统重构

### 6.1 当前问题

- 按 edge id 均匀偏移，不按类型分道 → 顺序边和伏笔边可能挤在同一位置
- 标签在曲线中点（t=0.5）→ 多条边标签 x 坐标几乎相同，必然重叠
- 因果边标签默认不显示 → 信息丢失

### 6.2 类型分道算法

**第一步：分组预处理**
所有边按 (from, to) 无向分组。

**第二步：泳道分配**

| edge_type | 基准泳道 | 说明 |
|-----------|---------|------|
| 0 顺序 | 0 | 中线，直线 |
| 1 因果 | +1 | 上方微弧 |
| 2 分支 | +2 | 上方大弧 |
| 3 汇合 | -1 | 下方微弧 |
| 4 伏笔 | -2 | 下方大弧 |
| 5 平行 | +3 | 上方更大弧 |
| 6 闪回 | -3 | 下方更大弧 |

同对同类型多条边：subOffset = subIndex × 0.4（第2条+0.4，第3条-0.4，交替）
finalLane = baseLane + subOffset

**第三步：路径计算**
```
控制点 C = 中点 M + 垂直方向 n × finalLane × LANE_HEIGHT(32px)
路径 = 二次贝塞尔 M P₀ C P₁
```

### 6.3 标签锚定效应端

标签位置从 t=0.5（中点）改为 **t=0.78**（靠近终点箭头前）：

```
P(0.78) = 0.0484·P₀ + 0.3432·C + 0.6084·P₁
```

理由：
- 靠近效应端，表达"这条边导致了什么"
- t=0.78 处不同泳道曲线的 y 分离度比 t=0.5 更大，标签天然错开
- 距终点约 1/5 曲线长度，不被节点卡片遮挡

标签样式：
- 半透明白色圆角底（rgba(255,255,255,0.9)），padding 3px 8px
- 字号 10px，颜色=边类型色
- textAnchor="start"，从标签点向右排
- 超长（>12字）截断 + hover 显示完整

标签显隐：
- 顺序边：不显示（语义自明）
- 因果/分支/汇合/伏笔：默认显示
- 人物关系边：默认显示关系子类型（如"母女""搭档"）

### 6.4 超量合并

同对节点边数 > 4 时：
- 渲染前 4 条（优先级：顺序>因果>伏笔>分支>汇合）
- 多余合并为终点旁 `+N` 徽标
- 点击徽标弹出侧边面板列出全部边

### 6.5 渲染层级（从底到顶）

```
1. 网格背景
2. 出场边（人→章，浅灰 opacity 0.2）
3. 剧情边（章→章，类型分道）
4. 人物关系边（人→人，独立偏移空间）
5. 人物节点（圆形）
6. 章节/卷节点（方形，最顶层，不被线穿过）
7. 标签（最顶层，白底，永远可读）
```

## 十一、风险与注意事项

1. **渲染内核抽象的回归风险**：阶段二必须保证 L1 零回归，建议每步提交后用已有项目手动验证 L1
2. **L2 性能**：50+ 章节 + 30+ 人物节点时，SVG 渲染可能卡顿。优化手段：人物节点用 DOM 而非 SVG、出场边简化为直线、视口外节点不渲染
3. **布局算法稳定性**：linear-branch 策略在分支复杂时可能重叠，需要迭代调参。force 策略作为备选
4. **关系边与剧情边的视觉干扰**：通过独立偏移空间 + 渲染层级解决，但在高密度 L2 画布上仍可能需要筛选器辅助
5. **数据库迁移**：V8 仅新增表，不修改现有表，向前兼容无风险
