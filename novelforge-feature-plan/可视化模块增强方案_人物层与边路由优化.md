# 可视化模块增强方案：人物层与边路由优化

> 基于 v1.1（节点=卷、三级下钻、泳道分层布局）的增量增强。
> 解决两个核心问题：①画布只有卷节点，人物关系无法可视化；②同端多边重叠，观感差。

---

## 一、问题诊断

### 1.1 人物层缺失

当前画布仅渲染 `volumes` 节点，`characters` 表（37 张人物卡）和 `character_mentions`（642 条提及记录）完全没有进入画布。导致：

- 无法直观看到"谁在哪个卷出场、谁是核心人物"
- 无法展示人物之间的关系（亲属/敌对/师徒/恋人）
- 无法展示人物与剧情线的关联（某人物属于主线还是暗线）
- 卷节点信息单薄，只有标题+字数

### 1.2 同端多边重叠

同一对卷节点之间存在多条边（顺序+因果+伏笔），当前每条边独立计算曲线路径，控制点相同，导致：

- 多条边完全重合或极近，视觉上像一条粗线
- 边标签互相覆盖，无法阅读
- 边类型（顺序/因果/分支/伏笔）无法区分

## 二、总体设计：三层画布架构

```
┌─────────────────────────────────────────────────────────┐
│  第三层：人物关系层（圆形节点 + 关系边）                    │
│    [叶文洁]──母女→[杨冬]  [汪淼]──搭档→[史强]            │
│         │                                               │
│  第二层：卷节点层（方形节点 + 剧情边）← 现有              │
│    [第一部] ──顺序──→ [第二部] ──顺序──→ [第三部]        │
│         ╲___ 因果 ___╱          ╲___ 因果 ___╱          │
│  第一层：剧情线泳道（背景色带）← 现有                     │
│    主线(蓝) ──────────────────────────────────           │
│    支线(金) ──────────────────────────────────           │
│    暗线(紫) ──────────────────────────────────           │
└─────────────────────────────────────────────────────────┘
```

三层共用同一套世界坐标系和 view transform（pan/zoom），通过筛选器控制显隐。

## 三、人物节点设计

### 3.1 节点形态

| 属性 | 卷节点 | 人物节点 |
|------|--------|---------|
| 形状 | 圆角矩形（现有） | 圆形 |
| 尺寸 | 固定 212×92 | 半径按提及次数动态：r = 16 + log₂(总提及) × 3 |
| 主色 | 所属剧情线色 | 角色类型色：主角=蓝、配角=灰、反派=红 |
| 内容 | 标题+字数+进度条 | 名字+角色标签+底部热度条 |
| 边框 | 2px 实线 | 2px 实线，跨卷人物加外环动画 |

### 3.2 人物节点位置计算（不存库，布局算法派生）

人物节点不存 map_x/map_y，由前端布局算法实时计算：

1. **确定出场卷集合**：查 `character_mentions` 聚合该人物出现的所有 volume_id
2. **锚点**：取出场卷的 map_x 平均值作为人物节点的 x 坐标
3. **垂直分布**：在锚点卷的上下两侧辐射排列
   - 主线人物（role=主角）：卷节点上方，y = 卷.map_y - 0.12
   - 配角：卷节点下方，y = 卷.map_y + 0.12
   - 同卷多人：按提及次数降序，水平等距排列，间距 = 0.08
4. **跨卷人物**：x 取所有出场卷的中点，y 放在卷连线上方 0.08

### 3.3 人物-卷连接边

人物节点与出场卷节点之间连一条**浅灰色细线**（opacity 0.3），表示"该人物在本卷出场"。线的粗细按该卷内提及次数编码。

这条边不占 edge_type，纯视觉辅助，筛选器可关闭。

## 四、人物关系边

### 4.1 新增数据表

```sql
CREATE TABLE character_relations (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    from_char   INTEGER NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
    to_char     INTEGER NOT NULL REFERENCES characters(id) ON DELETE CASCADE,
    rel_type    INTEGER NOT NULL,       -- 0亲属 1盟友/搭档 2恋人/夫妻 3敌对/背叛 4师徒/指引 5其他
    label       TEXT NOT NULL DEFAULT '',  -- 关系说明"母女""搭档""暗恋"
    volume_id   INTEGER REFERENCES volumes(id) ON DELETE SET NULL,  -- 关系发生卷（可空=跨卷）
    created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

### 4.2 关系边视觉编码

| rel_type | 线型 | 颜色 | 箭头 |
|----------|------|------|------|
| 0 亲属 | 实线 | #E1B98F（暖橙） | 无（双向） |
| 1 盟友/搭档 | 实线 | #5b8def（蓝） | 无（双向） |
| 2 恋人/夫妻 | 实线 | #EAA7B2（粉） | 无（双向） |
| 3 敌对/背叛 | 虚线 | #EA6668（红） | 单向（指向被背叛方） |
| 4 师徒/指引 | 点线 | #B56AD9（紫） | 单向（指向徒弟） |
| 5 其他 | 实线 | #9CA3AF（灰） | 无 |

### 4.3 关系边路由

人物关系边使用直线（人物节点间距足够，不需要曲线）。同端多边时同样适用第六章的偏移规则。

## 五、人物跨卷轨迹带

贯穿多卷的核心人物，在卷节点之间画一条**半透明纵向轨迹带**：

- 触发条件：人物在 ≥2 个卷有提及记录
- 视觉：从第一个出场卷到最后一个出场卷，画一条 3px 宽的半透明带（opacity 0.25），颜色=人物角色色
- 带的位置：在卷连线上方 0.06 处，多人物轨迹带垂直错开（间距 0.02）
- 效果：一眼看出"史强贯穿一二部""罗辑贯穿二三部""程心只在第三部"

轨迹带是纯渲染层，不存库，由 mentions 数据派生。

## 六、卷节点信息增强

### 6.1 节点内部新增元素

当前卷节点内容：标题 + 字数 + 进度条。

新增：

```
┌─────────────────────────────┐
│ 阶段1              🔴 2伏笔  │  ← 右上角伏笔徽标（活跃伏笔数）
│ 第一部 地球往事              │
│ 37章 · 165,357字             │
│ ▓▓▓▓▓▓▓▓▓▓░░░░ 进度条        │
│ ○汪淼 ○叶文洁 ○史强 ○丁仪    │  ← 核心人物行（提及Top4，小圆头像）
│ ── 古筝行动 ── 智子锁死 ──    │  ← 关键事件标签（卷纲提取或手动）
└─────────────────────────────┘
```

### 6.2 数据来源

- **核心人物行**：查 `character_mentions` 按 volume_id 聚合，取 mention_count 前 4
- **伏笔徽标**：查 `story_edges` WHERE edge_type=4 AND status=0（活跃伏笔），按 from_node 或 to_node 匹配当前卷
- **关键事件标签**：暂从 `volumes.summary` 提取前 2 个关键短语；后续可加 `volume_events` 表手动管理

## 七、筛选器与人物视角

### 7.1 顶部工具栏新增开关

在现有工具栏（自动布局/新建卷/剧情线/图例）右侧新增：

| 控件 | 类型 | 默认 | 作用 |
|------|------|------|------|
| 👤 人物 | toggle | 开 | 显示/隐藏人物节点和关系边 |
| 🔗 关系 | toggle | 开 | 显示/隐藏人物关系边（人物开时生效） |
| 🎯 剧情线 | dropdown | 全部 | 只高亮某条剧情线，其余变暗 |

### 7.2 人物视角模式

点击人物节点进入"人物视角"：

- 该人物节点高亮（放大 1.3 倍，外环发光）
- 该人物出场的卷节点高亮
- 与该人物有直接关系的人物节点高亮
- 其余所有元素 opacity 降至 0.15
- 画布顶部出现面包屑：`人物视角：史强 [退出]`
- 再次点击空白或"退出"恢复全图

## 八、同端多边路由优化

### 8.1 核心算法：类型分道 + 组内扇形

**第一步：按端点分组**

渲染前，将所有 `story_edges` 按 `(from_node, to_node)` 分组（无向，A→B 和 B→A 算同一组）。

**第二步：组内按类型排序，分配泳道**

每组内，按 edge_type 排序，每条边分配一个垂直偏移量：

```
偏移量 = 类型基准偏移 + 组内序号 × 步长
```

| edge_type | 类型基准偏移（归一化 y） | 说明 |
|-----------|------------------------|------|
| 0 顺序 | 0 | 中线，最直 |
| 1 因果 | +0.025 | 上方微弧 |
| 2 分支 | +0.05 | 上方更大弧 |
| 3 汇合 | -0.025 | 下方微弧 |
| 4 伏笔 | -0.05 | 下方大弧 |

同类型多条边：组内序号 × 0.015 叠加偏移，交替上下。

**第三步：贝塞尔曲线控制点**

```
中点 M = ((x1+x2)/2, (y1+y2)/2)
垂直方向 n = normalize(-(y2-y1), x2-x1)
控制点 C = M + n × 偏移量 × 节点间距系数
路径 = quadratic_bezier(P1, C, P2)
```

### 8.2 标签外置

边标签不再放在曲线中点（多边时互相覆盖），改为：

- 标签放在**靠近 to_node 的箭头前 15px** 处
- 标签背景：半透明白色圆角底（rgba(255,255,255,0.85)），padding 2px 6px
- 字号 10px，颜色=边类型色
- 同组多条边的标签沿垂直方向错开（与边偏移同步）

### 8.3 超量合并

同一对节点之间边数 > 4 时：

- 只渲染前 4 条（按类型优先级：顺序>因果>伏笔>分支>汇合）
- 第 5 条起合并为端点附近的 `+N` 徽标
- 点击徽标弹出侧边面板列出全部边

### 8.4 效果对比

```
【当前】
  A ≡≡≡≡≡≡≡≡≡≡≡≡≡≡≡≡≡ B    ← 3条叠成1条，标签打架

【优化后】
         ╭─ 因果:叶文洁发信号 ─╮
  A ────── 顺序:阶段推进 ──────→ B
         ╰─ 伏笔:宇宙社会学 ────╯
         (标签在箭头前，互不重叠)
```

| 变更 | 类型 | 说明 |
|------|------|------|
| `character_relations` | 新增表 | 人物关系，见 §4.1 |

| `story_edges` | 不变 | 边路由纯前端优化，不改数据 |

迁移：V8 仅新增 `character_relations` 表，不修改现有表。

## 十、实施优先级

| 阶段 | 内容 | 工作量 | 依赖 |
|------|------|--------|------|
| P0 | 同端多边路由优化（§8） | 小（~50行前端） | 无，可立即做 |
| P1 | 卷节点信息增强（§6） | 小（~30行前端） | 无 |
| P2 | 人物节点上画布 + 人物-卷连接边（§3） | 中（~150行前端） | 无 |
| P3 | character_relations 表 + 关系边渲染（§4） | 中（迁移+前端~200行） | P2 |
| P4 | 人物跨卷轨迹带（§5） | 小（~40行前端） | P2 |
| P5 | 筛选器 + 人物视角（§7） | 中（~100行前端） | P2 |

**建议顺序**：P0（边路由，立竿见影）→ P1（卷节点增强）→ P2（人物节点）→ P3（关系边）→ P4（轨迹带）→ P5（筛选视角）。
