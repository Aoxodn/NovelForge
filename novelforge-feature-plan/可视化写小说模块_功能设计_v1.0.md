## 一、背景与目标

### 1.1 痛点

现有写作闭环（卷→章树 + 三栏编辑器）对长篇小说有三类结构性短板：

1. **剧情只见局部**：单章视角看不到跨卷的因果链、多线并行与汇合。
2. **伏笔靠脑记**：埋设 / 回收关系散落在正文与作者笔记里，跨几十章极易断线。
3. **大纲是纯文本**：`project_info.outline` 只是自由文本，软件读不懂结构，后续"结构分析"能力无从落地。

### 1.2 目标

| 层  | 名称    | 一句话                                   |
| --- | ----- | -------------------------------------- |
| L1 | 故事地图 | 把大纲变成卡片 + 带类型连线的画布工作区，双击进正文      |
| L2 | 全书总览 | 一眼看到整本书的剧情线、伏笔埋设 / 回收、结构与进度         |
| L3 | 章节发展图 | 写作界面右栏随当前章节展示它的"来龙去脉"局部图           |

三者同源：**同一份图数据（story graph），三种呈现尺度**（全书 / 局部 / 单章上下文）。

### 1.3 非目标（本期不做）

- 全自由画布（Figma 式）——采用半自动布局，降低上手成本。
- 在线协作、账号、云同步——延续"本地优先、完全离线"的产品原则。
- AI 作为必选依赖——所有核心功能本地可跑，AI 是节点级可选能力。
- 实时多人编辑。

### 1.4 设计原则（沿用前序讨论的结论）

1. **画布是视图，不是数据源**：正文 / 大纲仍是结构化存储的唯一事实源，画布双向同步、可随时关闭。
2. **连线必须带类型**：顺序 / 因果 / 分支 / 汇合 / 伏笔回收，五类。
3. **AI 放节点上，不放全局**：选中节点出操作——扩写、连贯性检查、伏笔追踪。
4. **保持克制**：新功能不破坏现有写作闭环；老项目打开自动兼容（迁移只追加）。

## 二、功能全景

### 2.1 L1・故事地图（画布工作区）

入口：顶栏新增「故事地图」切换按钮，与三栏写作界面并列。

- 节点 = 章节（含纯规划节点，见 §4.1），卡片显示：类型 / 标题 / 状态色点 / 字数。
- 连线五类：`顺序`、`因果`（主线推进，实线）；`分支`、`汇合`（虚线）；`伏笔回收`（青点线，跨章呼应）。
- 首次进入：现有 卷→章 树自动铺成主线（半自动布局），用户再手动拖拽做分支与伏笔。
- 双击节点 → 进入正文编辑；选中节点浮出操作条（编辑正文 / 纲要 / AI）。
- 画布坐标（map_x / map_y）落库，重启不丢。

### 2.2 L2・全书总览（新）

入口：顶栏视图 Tab「全书总览」（与故事地图、时间线、人物关系并列）。三个子视图：

**a. 剧情线泳道**

- 按 `story_arcs`（主线 / 支线 / 暗线）分行，X 轴为**全局章节序**（口径见 §4.3）。
- 节点按 `chapters.arc_id`（单归属，V1.1 新增建模）归入对应泳道并着色；未归类的节点进「未分类」泳道，该泳道可在设置中折叠或隐藏。
- 泳道内保留关键连线（因果 / 分支 / 伏笔回收），hover 高亮该弧线全部节点与连线。
- 一眼可见：多线并行、断更段（弧线空缺）、汇合点。

**b. 伏笔总览**

- 全书的伏笔回收连线列表 / 网络，每条含：名称（label）、埋设章、回收章、跨度章数（**全局章节序差**，非卷内 sort_order 差）、状态（活跃 / 已回收 / 失效）、所属弧线。
- 过滤：只看未回收 / 已回收 / 失效 / 按弧线。
- **超期预警**：全局章节序（回收章）− 全局章节序（埋设章）> 阈值（默认 10 章，存 `settings` 表可配）→ 标 ⚠。跨卷伏笔同样正确（V1.1 修正）。

**c. 结构总览**

- 三幕 / 起承转合模板叠加在章节轴上，显示当前处于哪个结构阶段、各阶段字数占比。

### 2.3 L3・章节发展图（写作界面右栏，新）

- 位置：InfoPanel 新增「本章发展」卡片（顺序：项目 → 当前章节 → 本章纲要 → 本章出场 → **本章发展** → 版本快照）。
- 数据：`get_chapter_story_context(chapterId)` 返回：
  - 上游节点（入边，≤4 条，带连线类型）；
  - 下游节点（出边，≤4 条，带连线类型）；
  - 本章伏笔：本章埋设的、本章回收的；
  - 本章所属弧线（读 `chapters.arc_id`）。
- 呈现：迷你横向流式图 `上游 ← 当前章 → 下游`；伏笔单独一行，状态徽标（✓ 已回收 / ⚠ 未回收）。
- 交互：
  - 点上游 / 下游节点卡 → 切到故事地图并定位高亮该节点；
  - 点伏笔徽标 → 跳到埋设章或回收章；
  - 空态：无连线时提示「本章尚未纳入故事地图，可在地图中建立连接」。
- 意义：写这一章时永远知道"它从哪来、往哪去、有什么债（伏笔）没还"，不打断写作流。

## 三、视图关系

```
                同一份 story graph 数据
                 ┌──────────────────────────┐
                 │ chapters(+坐标/类型/弧线)   │
                 │ story_edges(五类连线)       │
                 │ story_arcs(剧情线)          │
                 └────────────┬─────────────┘
      ┌──────────────┬────────┴───────┬──────────────┐
      ▼              ▼                ▼              ▼
 三栏写作界面     故事地图(画布)      全书总览       章节发展图(右栏)
 (正文唯一事实源)  (全书/局部编辑)   (泳道+伏笔+结构) (单章上下文)
      └────── 双向同步：地图连线/坐标改动 ↔ 正文章节改动 ──────┘
```

## 四、数据模型（V6 迁移）

### 4.1 设计决策：节点 = 章节

不建独立 node 表，**节点直接复用 `chapters` 表**：

- 好处：正文、自动保存、版本快照、字数统计、回收站、人物出场统计全部免费复用，不存在"双数据源"。
- 纯规划节点（只规划不写正文的"事件 / 转折 / 支线"节点）= 一条 `status=0`、`content=''` 的空章节 + `node_type` 标注。
- 画布上删除节点 = 仅移除（清坐标 + 删关联边），章节本身仍保留在目录树；彻底删除章节仍走目录树右键 → 回收站。

**规划节点的三项配套（V1.1 补全，源于 `volume_id NOT NULL` 约束）：**

1. **落卷规则**：画布上新建规划节点，默认落入"当前选中章节所在卷"的末尾（`sort_order` 取该卷 max+1）；节点面板拖入时可在弹层里改选目标卷。规划节点必须挂卷，但目录树中显示为独立类型（见第 2 条），不与正文章节混淆。
2. **目录树显示**：`node_type != 0` 的章节在 ChapterTree 中显示独立图标（如 ◇ 空心菱形），与正文章节（●）区分；`ChapterMeta` 需追加 `node_type` 字段供前端判断。
3. **导出过滤**：`export.rs` 现有查询只过滤 `deleted_at IS NULL`，规划节点会以空白章混进成稿。需在全部三条范围查询（all / volume / chapter）追加 `AND node_type = 0`，纯规划章节不进成稿；后续如需"大纲版导出"再单独开入口。

### 4.2 迁移 SQL（追加到 `db/migrations.rs`，不改历史迁移）

```sql
-- V6：可视化写小说——故事地图 / 剧情线 / 伏笔

-- ① 剧情线（总览泳道 / 伏笔归类的载体）
--    先建被引用表，再对 chapters 做 ALTER，避免外键引用顺序问题
CREATE TABLE IF NOT EXISTS story_arcs (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    title      TEXT NOT NULL,
    kind       INTEGER NOT NULL DEFAULT 0,   -- 0=主线 1=支线 2=暗线
    color      TEXT NOT NULL DEFAULT '',     -- 泳道/节点着色（前端可覆写）
    summary    TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- ② 章节扩展：节点类型、画布坐标、弧线归属
ALTER TABLE chapters ADD COLUMN node_type INTEGER NOT NULL DEFAULT 0;
--   0=章节 1=事件 2=转折 3=支线 4=结局
ALTER TABLE chapters ADD COLUMN map_x    REAL;
--   画布坐标，归一化 0..1；NULL = 未排布（自动布局可覆盖）
ALTER TABLE chapters ADD COLUMN map_y    REAL;
ALTER TABLE chapters ADD COLUMN arc_id   INTEGER REFERENCES story_arcs(id) ON DELETE SET NULL;
--   节点的弧线归属（单归属，可空）。泳道分行 / 节点着色的直接依据；
--   与边级 story_edges.arc_id（单条边的归类，主要用于伏笔）职责不同，二者并存

CREATE INDEX IF NOT EXISTS idx_chapters_arc ON chapters(arc_id);

-- ③ 连线（顺序/因果/分支/汇合/伏笔回收）
CREATE TABLE IF NOT EXISTS story_edges (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    from_node  INTEGER NOT NULL REFERENCES chapters(id) ON DELETE CASCADE,
    to_node    INTEGER NOT NULL REFERENCES chapters(id) ON DELETE CASCADE,
    edge_type  INTEGER NOT NULL,             -- 0=顺序 1=因果 2=分支 3=汇合 4=伏笔回收
    arc_id     INTEGER REFERENCES story_arcs(id) ON DELETE SET NULL,
    label      TEXT NOT NULL DEFAULT '',     -- 因果说明 / 伏笔内容
    status     INTEGER NOT NULL DEFAULT 0,   -- 伏笔：0=活跃 1=已回收 2=失效；其余类型固定 0
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    CHECK (from_node != to_node)
);

CREATE INDEX IF NOT EXISTS idx_edges_from ON story_edges(from_node);
CREATE INDEX IF NOT EXISTS idx_edges_to   ON story_edges(to_node);
CREATE INDEX IF NOT EXISTS idx_edges_arc  ON story_edges(arc_id);
```

> **关于唯一约束（V1.1）**：不加 `(from_node, to_node, edge_type)` 唯一约束——同一对章节间埋多条伏笔是合理场景。重复风险只存在于顺序边，处理方式见 §5.2 布局规则：顺序边作为派生数据整体重建，不在数据库层约束。

### 4.3 字段口径

| 字段                      | 说明                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `chapters.node_type`    | 画布与总览的节点造型依据；现有章节默认 0，行为不变；导出按 `node_type = 0` 过滤（§4.1）                              |
| `chapters.map_x/map_y`  | 画布坐标，**归一化 0..1**；NULL = 未排布（自动布局可覆盖）                                              |
| `chapters.arc_id`       | 节点弧线归属（单归属，可空）。泳道分行与节点着色的依据；NULL 进「未分类」泳道                                            |
| `story_edges.edge_type` | 预留扩展位（如未来"时间跳跃"边 = 5）                                                                |
| `story_edges.status`    | 仅伏笔边有意义；回收 = 作者手动标记或回收节点完稿时的轻提示（§6.2）                                              |
| `story_edges.arc_id`    | 边级归类（伏笔归入暗线等），与节点级 `chapters.arc_id` 职责不同                                          |
| **全局章节序**（口径，非字段）       | 一切跨章计算（超期预警、泳道 X 轴、跨度章数）统一使用 `ORDER BY volumes.sort_order, chapters.sort_order, chapters.id` 联表得出的全局序，**禁止直接用 `chapters.sort_order` 跨卷相减**（它是卷内序号，跨卷无意义）。与 `export.rs` 现有排序口径一致 |

### 4.4 兼容性

- 迁移只追加，`PRAGMA user_version` 门控，旧项目打开自动补表。
- `chapters` 新列均有默认值或可空，现有读写路径不破坏；仅三处现有查询需要最小改动：`ChapterMeta` 追加 `node_type`（目录树图标）、导出过滤（§4.1 第 3 条）、以及本模块新增的图查询。
- 现有 `project_info.outline` 纯文本大纲**保留**（总览视图作为"结构入口"，文本大纲继续用于导出与速览）。
- **回收站章节（V1.1）**：`deleted_at` 非 NULL 的章节在故事地图 / 总览中**隐藏**（边保留，不触发级联删除）；章节从回收站恢复即恢复显示；彻底删除时由 `ON DELETE CASCADE` 自动清理关联边。语义：回收站 = 暂时离开图，彻底删除 = 连边一起消失。

## 五、界面与交互明细

### 5.1 入口与视图体系

- 顶栏（TopBar）新增：`故事地图`、`全书总览` 两个按钮（与现有 搜索 / 卡片 / 统计 等图标并列）。
- ProjectView 增加 `viewMode: 'editor' | 'map' | 'overview'` 状态：
  - `map` / `overview` 时渲染对应视图，保留三栏组件挂载（同专注模式的思路，状态不丢）。
- 时间线 / 人物关系两个视图暂列 V2（见 §八），本期文档先定义数据结构。

### 5.2 故事地图（画布）

- **节点**：单击选中（右抽屉显示详情）、拖拽移动（坐标防抖落库）、双击进入正文编辑。
- **连线**：从节点边缘拖到另一节点 → 弹类型选择（顺序 / 因果 / 分支 / 汇合 / 伏笔回收，伏笔需填 label 与弧线）；单击连线选中（可改 label / 标记回收 / 删除）。
- **新建**：左侧节点面板拖类型到画布 = 创建规划节点（默认落当前卷末尾，可改选，见 §4.1）；或 Ctrl+N 走现有流程后自动入图。
- **布局**：`自动布局` 按钮 = 按全局章节序重置主线坐标，并**删除后重建全部顺序边**（顺序边是派生数据，重建保证无重复；重建前弹确认，因果 / 分支 / 汇合 / 伏笔边不受影响）。手动拖拽过的节点不强制覆盖坐标（提示后执行）。
- **回收站章节**：地图中不显示；如某章节有边但其章节在回收站，总览的伏笔列表中标注「（章节在回收站）」。
- **快捷键**：双击编辑 / Delete 移除选中（先问是否仅移除）/ Ctrl+S 保存坐标。
- **画布实现（V1.1 决策）**：手写 SVG，不引入 @xyflow/react 等图库——与项目近零依赖风格一致，pan/zoom、命中检测、连线交互自实现；>200 章启用视口剔除（culling），坐标落库天然支持。

### 5.3 全书总览

- 泳道视图：每弧线一行（节点按 `chapters.arc_id` 归行）；节点芯片按全局章节序排布；连线跨泳道时画桥接线。
- 伏笔总览：表格行 + 网络图切换；过滤条件栏固定顶部。
- 结构总览：三幕 / 起承转合阶段带；与泳道共用同一 X 轴，可叠加开关。
- 空态引导：无弧线 / 无伏笔时给出引导文案与建线入口。

### 5.4 章节发展图（右栏卡片）

- 数据实时性：随 `lastSavedAt` / 地图改动事件刷新（复用现有 `nf:cards-updated` 事件模式）。
- 展示上限：上游 / 下游各 ≤4 条，超出显示「+N 条，点此打开地图」。
- 与 InfoPanel 风格一致：卡片化、chips 化，不引入新交互范式。

## 六、状态机

### 6.1 章节状态（沿用现有，不新增）

```
status 0=草稿(空心点) ── 完稿 1=实心点
```

画布与总览的色点直接读 `chapters.status`，与目录树同源，不改现有枚举。

### 6.2 伏笔状态机

```
创建伏笔边(埋设) ──→ 活跃(默认) ──→ 已回收(回收章出现 / 手动标记)
                        │
                        └──→ 失效(作者标记，如剧情废弃)
```

- 回收建议：当 `to_node`（回收章）`status=1` 完稿时，在 InfoPanel「本章发展」卡内给**非阻塞轻提示**"是否标记该伏笔已回收"——不用模态弹窗，不打断写作流（V1.1 明确交互形态）。
- 超期预警：**全局章节序**（回收章）− **全局章节序**（埋设章）> 阈值（默认 10 章，`settings` 表可配置）→ 总览与右栏标 ⚠。跨卷伏笔用同一公式天然正确。

## 七、AI 介入（本地规则优先，零 Token）

| 能力     | 输入                        | 输出                       | 实现                                      |
| ------ | ------------------------- | ------------------------ | --------------------------------------- |
| 节点扩写提示 | 节点 title/summary + 相邻节点摘要 | 情节点建议（要点式）               | 本地规则：基于大纲模板与相邻节点梗概拼接，结构化建议              |
| 连贯性检查  | 本章实体（mentions）+ 上游节点      | 人物 / 地点 / 时间与前文冲突提示      | 复用 characters/locations + mentions 精确匹配 |
| 伏笔追踪   | 当前节点                      | 该节点相关伏笔列表（埋设 / 活跃 / 未回收） | 直接查 story_edges (edge_type=4)         |

## 十、风险与决策记录

| 决策点  | 选择                 | 理由                             |
| ---- | ------------------ | ------------------------------ |
| 节点模型 | 节点 = 章节（空章 = 规划节点） | 复用全部现有能力，避免双数据源                |
| 布局   | 半自动（自动主线 + 手动微调）   | 全自由画布对普通作者门槛过高                 |
| 伏笔建模 | 边 + 状态机 + 弧线归类     | 覆盖埋设 / 回收 / 超期，不做实体级引用解析（成本过高） |
| 坐标存储 | 归一化 0..1           | 视口尺寸变化不失效                      |
| 删除语义 | 画布移除 ≠ 删章节         | 章节删除仍走回收站，防止误删正文               |
| 大项目  | 视口剔除 + 坐标落库        | 200 章级性能可控                     |
| 跨章序号 | 全局章节序（联表排序）        | `sort_order` 是卷内序号，跨卷相减会算错超期预警；与导出排序口径统一 |
| 弧线归属 | `chapters.arc_id` 单归属 | 泳道分行/节点着色需要节点级归属；边级 arc_id 继续负责单边归类 |
| 画布实现 | 手写 SVG，零依赖         | 与项目近零依赖风格一致；交互复杂度可控；不引 @xyflow/react |
| 顺序边语义 | 派生边，自动布局整体重建       | 免数据库唯一约束，天然无重复；其余四类边是手工数据不受影响 |
| 规划节点导出 | 导出过滤 `node_type = 0` | 规划卡片不混入成稿；大纲版导出留待后续 |

## 十一、已确认决策（V1.1，原"待确认问题"）

1. **纯规划节点**：允许（它就是大纲卡片），但以三项配套为前提——落卷规则、目录树独立图标、导出过滤（§4.1）。
2. **伏笔超期阈值**：默认 10 章，存 `settings` 表做成每项目可配置项；不做"按字数 / 卷数自适应"——口径复杂收益低。
3. **伏笔回收自动建议**：InfoPanel 卡片内非阻塞轻提示，不用模态弹窗（设计原则"不打断写作流"）。
4. **时间线视图口径**：采用结构时间线（章节顺序）。正文时间表达式不可行——`timeline_markers` 已在 V3 迁移中因识别精度不可达被废弃，同一技术路线不做第二次。
